# Нарезка Veo-роликов в спрайт-листы

Пайплайн: **референс → генерация → замер → единое окно → хромакей+despill →
сборка листа → числовая приёмка**.

Главное правило всего пайплайна: **все кадры одной анимации режутся ОДНИМ
неподвижным окном кропа**. Покадровое выравнивание всегда добавляет дрожь
(джиттер), которая сильнее всего заметна на плащах, шерсти и длинных
силуэтах. Кадры из одного ролика со статичной камерой уже согласованы
между собой — их нельзя «улучшать» по отдельности.

## 0. Инструменты

```bash
pip install pillow numpy scipy --break-system-packages
```

`ffmpeg` для распаковки кадров, `PIL` + `numpy` для обработки,
`scipy.ndimage` для поиска связных компонент (отделить объект от
водяного знака и мусора).

## 1. Референс-кадр перед генерацией

Модель, получив плотный кадр «объект во весь экран», нарисует ещё крупнее
и обрежет края. Всегда готовь «отдалённый» стартовый кадр:

```python
from PIL import Image
obj = Image.open('object.png').convert('RGBA')   # готовый дизайн, прозрачный фон
W, H = 1920, 1080
canvas = Image.new('RGBA', (W, H), (61, 121, 69, 255))   # зелёный хромакей
target_h = int(H * 0.50)        # 0.35–0.62, подбирается по пропорциям объекта
scale = target_h / obj.height
small = obj.resize((int(obj.width*scale), target_h), Image.LANCZOS)
canvas.paste(small, (W//2 - small.width//2 - 150, int(H*0.88) - target_h), small)
canvas.convert('RGB').save('reference.png')
```

Долю высоты подбирай по обратной связи: 0.35 обычно «слишком мелко»,
0.62 годится для коренастых широких существ, 0.48–0.55 — универсально.

## 2. Формулировка промпта — что ломается регулярно

| Проблема | Причина | Как писать |
|---|---|---|
| Персонаж развернулся к камере | `front-facing` и `profile` в одном промпте — противоречие | только `strict side-view profile`, без `front-facing` |
| Персонаж зеркалится | направление задано абсолютной стороной кадра | `in the direction it is facing`, плюс `do not flip, mirror, or turn` |
| Разворот на «активном» глаголе | `rears back`, `winds up` читаются как поворот корпуса | описывай голой геометрией: `pulls arm back behind itself` |
| Наезд камеры в начале | игнор `no zoom` | не лечится промптом — режь первые кадры (см. §4) |
| Зелёный эффект не вырезается | зелёный VFX на зелёном хромакее | фон чёрный, альфа = яркость (аддитивный ключ) |
| Отказ по копирайту | силуэт похож на чужую IP | измени пропорции/детали силуэта или дай более короткий промпт |

Скелет промпта из четырёх блоков: **ракурс → кадрирование → геометрия
действия → запрет эффектов**. Всегда добавляй
`no text, no watermark, no camera shake, no motion blur`.

## 3. Распаковка и первичный замер

```bash
ffmpeg -i clip.mp4 -y f_%03d.png
```

Дальше — **всё меряй числами, не на глаз**. Базовая функция: bbox самой
крупной связной компоненты (отсекает водяной знак и артефакты).

```python
import numpy as np
from PIL import Image
from scipy import ndimage

def bbox(path, bg_thr=15):
    a = np.array(Image.open(path).convert('RGB')).astype(int)
    r, g, b = a[:,:,0], a[:,:,1], a[:,:,2]
    obj = ~((g > r + bg_thr) & (g > b + bg_thr))     # не-зелёное
    lbl, n = ndimage.label(obj)
    if n == 0:
        return None
    sizes = ndimage.sum(obj, lbl, range(1, n+1))
    ys, xs = np.where(lbl == np.argmax(sizes) + 1)
    return xs.min(), xs.max(), ys.min(), ys.max()
```

Прогони по всем кадрам и распечатай — по этой таблице видно:
- **где начинается и кончается полезная фаза** (для одноразовых эффектов —
  где растёт и где гаснет площадь);
- **есть ли наезд камеры** (bbox монотонно растёт в первых ~8-10 кадрах);
- **дрейфует ли объект** (сравни низ фигуры между кадрами);
- **не развернулся ли персонаж** — ищи устойчивый асимметричный признак
  (светящийся глаз, цветная деталь) и смотри его долю от края bbox.

## 4. Наезд камеры

Частый артефакт: первые 8-10 кадров модель «наезжает» с уменьшенного
масштаба до полного, даже при `no zoom` и стартовом изображении.
Перегенерация не нужна — найди кадр, где bbox перестаёт расти, и начинай
нарезку с него.

## 5. Выбор кадров

Число кадров в листе ≠ число кадров в ролике. 24 fps нужны видео, игре
хватает 10-16 кадров на цикл; лишнее только раздувает текстуру.

Для равномерного движения:

```python
idxs = np.linspace(start, end, N).astype(int)
```

Для движения с разной скоростью (замах быстрый, удержание статичное) —
**неравномерный шаг**, гуще там, где движение:

```python
idxs = sorted(set(
    list(range(40, 72, 3)) +      # быстрая фаза  — каждые 3
    list(range(75, 156, 12)) +    # удержание     — каждые 12
    list(range(160, 179, 3))      # возврат       — каждые 3
))[:24]
```

## 6. Единое окно кропа + хромакей + despill

Ключевой шаг. Обрати внимание: **хромакей применяется ДО кропа**, а окно
кладётся на прозрачный холст. Если резать сначала, PIL добьёт выход за
границу кадра чёрным, и он посчитается непрозрачным объектом.

```python
def frame(path, scale, dx, dy, CW, CH):
    src = Image.open(path).convert('RGB')
    nw, nh = int(src.width*scale), int(src.height*scale)
    a = np.array(src.resize((nw, nh), Image.LANCZOS)).astype(np.float64)
    r, g, b = a[:,:,0], a[:,:,1], a[:,:,2]

    spill = np.maximum(g - np.maximum(r, b), 0)   # зелёный подмес
    alpha = np.clip(255 - spill*5, 0, 255)        # альфа из «зелёности»
    g2 = g - spill                                # DESPILL: гасим подмес

    rgba = np.dstack([r, g2, b, alpha]).astype(np.uint8)
    img = Image.fromarray(rgba, 'RGBA')
    canvas = Image.new('RGBA', (CW, CH), (0,0,0,0))
    canvas.paste(img, (-dx, -dy), img)            # ОДНО окно для всех кадров
    return canvas
```

Если фон не чистый зелёный (модель иногда даёт серо-зелёный или вовсе
серый), порог по «зелёности» не доберёт до нуля и оставит полупрозрачную
дымку. Тогда — по евклидову расстоянию до реального цвета фона, взятого
из угла **каждого** кадра:

```python
bg = arr[5, 5]
dist = np.sqrt(((arr - bg)**2).sum(axis=2))
alpha = np.clip((dist - 12) * 10, 0, 255).astype(np.uint8)
```

Для светящихся эффектов на чёрном фоне альфа берётся из яркости:

```python
alpha = np.clip(arr.sum(axis=2) / 3, 0, 255).astype(np.uint8)
```

## 7. Сведение к существующим анимациям (IoU)

Чтобы персонаж не прыгал при смене анимации, новый лист сводится к
эталонному (обычно `idle`). **Совмещать по IoU-наложению силуэтов, а не по
медиане ступней** — при вынесенной в сторону руке или разъезжающихся в
выпаде ногах медиана уезжает.

```python
CW, CH = 394, 296
ref = np.array(Image.open('idle.png').convert('RGBA'))[0:CH, 0:CW, 3] > 128

def iou_at(obj, nw, nh, dx, dy):
    c = np.zeros((CH, CW), bool)
    ys0, ys1 = max(0,dy), min(nh, dy+CH)
    xs0, xs1 = max(0,dx), min(nw, dx+CW)
    if ys0 >= ys1 or xs0 >= xs1:
        return 0
    c[ys0-dy:ys1-dy, xs0-dx:xs1-dx] = obj[ys0:ys1, xs0:xs1]
    i, u = (c & ref).sum(), (c | ref).sum()
    return i/u if u else 0
```

**Диапазон поиска считай из геометрии, а не наугад** — на этом легко
потерять час. Стартовый масштаб: `рост_эталона / рост_фигуры_в_исходнике`.
Стартовое смещение: `dx0 = x_левый_край*scale - x_левый_край_эталона`,
`dy0 = y_низ*scale - y_низ_эталона`. Дальше перебор ±20px вокруг.

Здоровый IoU для одного персонажа в похожей позе — **0.80-0.87**. Если
получается 0.2-0.4 — почти наверняка диапазон поиска не накрывает верное
значение, а не «позы разные».

## 8. Размер клетки

- **Один персонаж, много анимаций** → одна общая квадратная (или
  фиксированная) клетка для всех: только так якорь остаётся на месте при
  переключении состояний.
- **Анимация шире базовой позы** (замах, выпад) → сначала **проверь
  числами**, влезает ли она в стандартную клетку. Часто влезает, и заводить
  свою ширину не нужно. Если не влезает — бери **тот же масштаб пикселей**,
  что у базовой анимации, но более широкий холст.
- **Одноразовые VFX** (снаряд, взрыв, аура) → у каждого своя рамка под его
  форму. Общая квадратная клетка тут только тратит память на пустоту.
- Держи ширину листа **под 4096px** (лимит текстуры на слабых GPU) —
  раскладывай сеткой 6×4 вместо 12×2 и передавай число колонок в код явным
  параметром.

## 9. Сборка листа

```python
COLS, ROWS = 6, 4
sheet = Image.new('RGBA', (CW*COLS, CH*ROWS), (0,0,0,0))
for n, idx in enumerate(idxs):
    sheet.paste(frame(...), ((n % COLS)*CW, (n // COLS)*CH))
sheet.save('anim_name.png')
```

Имя файла при переделке — **всегда новое**, иначе кеш подхватит старое.

## 10. Приёмка — только по числам

Проверяй **на двух порогах альфы (128 и 32)**: на 32 дрейф и остатки фона
проявляются сильнее.

```python
for thr in (128, 32):
    bots, tops, hs = [], [], []
    for r in range(ROWS):
        for c in range(COLS):
            cl = alpha[r*CH:(r+1)*CH, c*CW:(c+1)*CW]
            ys, xs = np.where(cl > thr)
            bots.append(ys.max()); tops.append(ys.min())
            hs.append(ys.max() - ys.min())
    print(thr, "низ:", min(bots), max(bots), "| верх:", min(tops), max(tops))
```

Чек-лист:
- строка ступней (низ фигуры) — разброс близок к нулю;
- альфа в четырёх углах листа ровно **0**, в пустых полях максимум **0**;
- зелёный подмес в полупрозрачных краях **0** (проверка despill);
- нет пустых и продублированных клеток в конце;
- рост фигуры и верхняя кромка совпадают с эталоном ±1-2px.

Проверка despill:

```python
semi = (a[:,:,3] > 20) & (a[:,:,3] < 220)
print((a[:,:,1][semi] - np.maximum(a[:,:,0][semi], a[:,:,2][semi])).max())  # ждём 0
```

## 11. Честность в отчёте о остаточном движении

Если после единого окна остаточный разброс не нулевой — **проверь
исходник, прежде чем чинить**. Часто это реальное движение персонажа
(переминается, проседает в выпаде), а не артефакт нарезки:

```python
# тот же замер, но по исходным кадрам, до масштаба и кропа
# если разброс_исходника * scale ≈ разброс_в_листе — кроп не добавил ничего
```

Не «исправляй» такое покадровым сдвигом: это вернёт ровно ту дрожь, от
которой уходили. Сообщи цифры и происхождение.

Отдельно: критерий «разброс центра ступней = 0» неприменим к анимациям,
где ноги реально расходятся (выпад, прыжок, широкий шаг). Там медиана
ступней гуляет на десятки пикселей — это содержание, а не дефект.

## 12. Что отдавать вместе с листом

- размер листа, размер клетки, число колонок и рядов, число кадров;
- зациклена анимация или одноразовая;
- для атак — номер кадра с пиком и координаты точки вылета снаряда
  (центр ладони/когтя) **внутри клетки** на этом кадре;
- результаты приёмки числами.

## 13. Проверка глазами — за пользователем

Контактный лист (все кадры сеткой на сером фоне) и GIF-превью собираются
быстро и решают почти все споры о том, «нормально ли смотрится»:

```python
frames[0].save('preview.gif', save_all=True, append_images=frames[1:],
               duration=90, loop=0, optimize=True)
```

Числа ловят джиттер, обрезку и грязный фон. Правдоподобность движения,
анатомию после зеркалирования и «читается ли жест» числа не ловят —
показывай контактный лист и спрашивай.
