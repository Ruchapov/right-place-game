## Maps System (ГОТОВО — 6/6 карт, интегрированы)

Все 6 карт пула собраны, проверены на проходимость и сданы одним пакетом
`RightPlace_maps.zip` (сетки .txt + слоты .json + README.md). Инструменты
проверки — `tools/map_tools.py` (`lint`, `report`, `wave`, `debug`).

**Критично при любой новой правке рельефа:** проверка обязана требовать
**2 тайла воздуха** над каждой точкой стояния (герой 128px = 2 тайла), а не 1.
Старые проверки этого не делали и давали ложноположительный "проходимо" —
несколько итераций карты F ловили именно эту ошибку.

Единая схема слот-файла (JSON), координаты `[x,y]` с 0, левый верхний угол:
```
{ mapId, name, start:[x,y],
  enemyClusters:[{zone, points:[[x,y]x3]}],  // группа = 3 врага, макс 2 на точку, макс 9/забег
  reward:[[x,y]], hazard:[[x,y]],
  npc:{smuggler:[[x,y]]|null, puzzle:[[x,y]]|null}, boss:[x,y]|null,
  obelisk:{...}  // только карта F
}
```
Каждый забег закрывает **ровно 3 события**, рандомных из слот-пулов карты.

### Особая механика: тайник карты D (OPEN/SEALED, 50/50) — ГОТОВО
При заходе на карту D — бросок 50/50: OPEN или SEALED (катится на СЕРВЕРЕ, в
`pickRunMapFile()`, `server/src/runEvents.ts` — слот D там отдельным броском
выбирает `map_D_OPEN.txt`/`map_D_SEALED.txt`; debug-кнопка "D Тайник (50/50)"
в App.tsx осталась и кидает свой такой же бросок, но она шлёт серверу уже
готовое имя файла). OPEN → тайник доступен, спуск на дно ямы открыт, И
Контрабандист ГАРАНТИРОВАН одним из событий забега. SEALED → тайник завален, Контрабандиста
нет.
Файлы переименованы к простому шаблону: `map_D_OPEN.txt` / `map_D_OPEN_slots.json`
/ `map_D_SEALED.txt` / `map_D_SEALED_slots.json` (старые map_D_tainik*.txt и
map_D_slots.json удалены). `slotsFileForMap` в Explore.tsx получила спец-ветку
для карт с суффиксом состояния (map_D_* → слоты = имя.txt с заменой .txt на
_slots.json; остальные карты A/B/C/E/F — по первому токену, как раньше).
⚠️ Старый дизайн (был тут раньше: "пустой ролл Смуглера заваливает тайник")
БОЛЬШЕ НЕ АКТУАЛЕН — причина/следствие перевёрнуты.

**Гарантия OPEN→Контрабандист — РЕАЛИЗОВАНА** в `setup()` (Explore.tsx),
прямо перед формированием тройки событий: при `mapFile.startsWith('map_D_OPEN')`
кандидат-смуглер вынимается из общего пула (`buildEventCandidates(slots)`) и
ставится ПЕРВЫМ элементом `chosenEvents`, оставшиеся два добираются обычным
`pickRandom` из пула БЕЗ него (не задваивается). Порядок тройки НАМЕРЕННО не
перемешивается — иначе смуглер не был бы гарантирован *в конкретной позиции*,
хотя гарантия попадания в тройку сохранилась бы.
На SEALED ничего дополнительно исключать не нужно: в `map_D_SEALED_slots.json`
`npc.smuggler = null`, а `buildEventCandidates` молча пропускает типы без точек
— смуглер туда и так не попадает в пул.
⚠️ Известное следствие: иконка Контрабандиста в HUD-плите всегда ПЕРВОЙ (левое
гнездо из трёх) при OPEN — то есть состояние карты D читается по HUD ещё до
спуска в яму (спойлер по факту гарантии + фиксированного порядка). Если это
станет проблемой — чинить перемешиванием итоговой тройки (`chosenEvents`)
ПОСЛЕ вставки смуглера, а не отказом от гарантии.
⚠️ Механизм узкий и специфичный для карты D: проверка `mapFile.startsWith(...)`
на месте вызова, НЕ общий флаг `pinned` на `EventCandidate` — такого поля в
типе нет и заводить его для этой одной гарантии намеренно не стали. Если
Контрабандист появится на других картах (см. "Не хватает по изначальному
распределению" — должен быть ещё на B), там он будет рядовым равновероятным
событием без гарантии, если явно не решить иначе.

### Особая механика: Обелиски (карта F, заменяет Загадку) — ГОТОВО
10 точек-кандидатов на всех 4 ярусах карты, `slots.obelisk?.points`. Обелиск —
рядовое событие рулетки 3 событий (см. "Готовые ассеты — Загадка-обелиск" выше
для полной механики/констант/арта): не выпал в тройку — на карте его нет.
Выпал → 1 обелиск в `idle` в случайной точке → удар → `burning` + старт события
+ таймер 30 сек + доспавн ещё 3 (рандом из оставшихся точек) → каждый следующий
удар +15 сек (таймер НЕ фиксированный) → все 4 сбиты = золото 60–120 +
`closeEvent`, обелиски гаснут в `idle` декорацией; таймер истёк = смерть героя
через обычный путь death, событие не закрывается.
✅ Вопрос "максимальная дистанция между обелисками может не влезть в 30 сек"
ЗАКРЫТ добавкой времени за удар (таймер растёт, не фиксирован).

### Не хватает по изначальному распределению
Смуглер должен быть на B и D (сделан только на D). Загадка — на B и F (на F
заменена обелисками, на B не сделана вообще). Если нужно 1:1 соответствие —
доделать слоты на B.

### Пробелы в проверках (найдены в Фазе 1)
- free() внутри build() исключает из графа клетки с занятой клеткой головы.
  Из-за этого report() даёт 100% проходимости, хотя есть места, где стоять
  нельзя (герой 2 тайла). Нашли только руками в игре на карте A.
- Нужен клиренс-чек (2 тайла воздуха над каждой точкой стояния) — report()
  сам по себе НЕ достаточен. Проверка lint_clearance это ловит.
- can() не проверял препятствия на пути прыжка (уже починено в build()).
- Карты A-F нарушают клиренс в 2-4 местах каждая, ждут точечной правки.

### Рендер карты
- Красивый рендер карты (как "mapA final") делает НЕ `render_lib.py`
  (ВНЕШНИЙ инструмент, вне репозитория, лежит у Андрея на машине; он
  процедурный и даёт рябь), а модуль `src/mapRenderer.ts` — перенесён из
  редактора карт `_ref/map_editor.html` (Canvas2D).
- Ключ красоты: `drawSolid` берёт КУСОК текстуры masonry под каждый тайл
  (`drawImage` с обрезкой sx,sy,tp), а не ужимает весь PNG; обводка
  рисуется только по краям, смотрящим в воздух (air-проверки); `=`
  платформы берут нижние 45% текстуры.
- `renderMapToCanvas({grid, decor, tileSize}) -> HTMLCanvasElement`,
  который в `Explore.tsx` оборачивается в `Texture.from(canvas)` и
  показывается как фоновый Sprite. Коллизия отдельно из .txt сетки.
- Текстура masonry и декор-спрайты вшиты в `mapRenderer.ts` как base64
  (взяты из `_ref/map_editor.html`). Папка `_ref/` в `.gitignore`.
- **Обновление**: `renderMapToCanvas({grid, decor, tileSize, theme})` —
  добавлен 4-й параметр `theme` (см. "Тематическая система карт" ниже).
- **Текстуры карты БОЛЬШЕ НЕ base64 в коде** (было — вшиты из
  `_ref/map_editor.html`, см. предыдущий пункт). Теперь отдельные PNG в
  `public/assets/`, грузятся асинхронно, как спрайты героя/зверя. Причина:
  30+ текстур в base64 раздували JS-бандл, который грузится при каждом
  заходе. Папка `_ref/` по-прежнему в `.gitignore`.
- **Мёртвый остаток той base64-схемы удалён**: константа `SPRITES`
  (spikes/chest/obelisk вшиты как base64) вычищена из `mapRenderer.ts`
  (аудит мёртвого кода). `spikes` теперь приходит ТОЛЬКО из
  `objects/spikes.png` — из этого блока он и раньше не читался (ключ тут
  же перезаписывался реальным файлом при слиянии); `chest`/`obelisk` из
  него не читались НИКОГДА ни на каком этапе.
- Канвас карты **прозрачный** там, где нет тайлов — `drawBackdrop()`
  больше НЕ заливает холст градиентом. Иначе он перекрывал бы собой живые
  слои параллакса (ловили этот баг: фон грузился, но был не виден —
  сплошная тёмно-фиолетовая заливка вместо картинки).

### Тематическая система карт (фон + кладка + декор)
Одна тема задаёт СРАЗУ три вещи: пару фонов параллакса, атлас кладки и
набор из 6 декораций. Тема выбирается по mapId в `BACKDROP_BY_MAP`
(`explore/constants.ts`), тип — `BackdropPreset` в `mapRenderer.ts`.

⚠️ **С 07.10.2026 это верно для ДВУХ тем из трёх.** У темы `graveyard` (карты
A и F) кладки и декора в игре БОЛЬШЕ НЕТ: платформы и декор этих карт — готовый
слой-картинка, см. «Готовые слои карт A и F» ниже. От темы у них остался только
фон. Тип `TileTheme` (`mapRenderer.ts`) — это темы, которые умеют рисовать
плитку, и кладбища среди них нет: вызвать плиточный рендер с этой темой не даст
компилятор.

| Тема | Карты | Чем рисуются платформы и декор | Характер |
|---|---|---|---|
| `graveyard` | A, F | готовый слой из одобренного арта | серый камень с мхом, арки с черепами и плакальщицами, свечи, урны |
| `throne_room` | C, E | плитка из атласа + 6 декораций | тёплый камень, багровая ткань, троны/канделябры |
| `flooded_crypt` | B, D | плитка из атласа + 6 декораций | мокрый тёмный камень, саркофаги/кости/цепи |

Файлы (все в `public/assets/maps/`):
- `backgrounds/bg_<theme>_far.png` + `bg_<theme>_mid.png` — 1125×900, у
  `throne_room` и `flooded_crypt`; у `graveyard` — `bg_graveyard_far.webp`
  (1405×1119) и `bg_graveyard_mid.webp` (1402×1122, с прозрачностью);
  расширение по теме — `BACKDROP_EXT` в `mapRenderer.ts`
- `textures/masonry_<theme>.png` — атлас 1064×532, сетка 8 колонок × 4 строки
  (двух тем; `masonry_graveyard.png` убран)
- `textures/<theme-prefix>_*.png` — 12 декораций (6 на тему), префиксы
  `throne_`, `crypt_` (шесть `grave_*` убраны)
- `art/map_A_serpentine.webp`, `art/map_F_sanctuary.webp` — готовые слои A и F

**Игровые объекты живут ОТДЕЛЬНО от декора и НЕ зависят от темы:**
`chest` (сундук+мимик), `spikes` (шипы), `obelisk` (событие карты F) —
у них своя логика, тематический набор их не трогает.

### Параллакс в Explore (2 живых слоя, НЕ часть канваса карты)
`bgFar`/`bgMid` — `TilingSprite`, добавлены в `app.stage` ДО
`worldContainer` (то есть позади карты) и НЕ внутрь него. Если положить
их внутрь `worldContainer`, они поедут 1:1 с картой и эффекта глубины
не будет вообще. Скорости в `updateCamera`: far ×0.15, mid ×0.4
(карта — 1:1) — одни на все темы. Плюс `bgDim` (Graphics) поверх обоих слоёв —
контраст, чтобы кладка/декор не терялись на детальном фоне.
`tileScale` пересчитывается на `renderer.on('resize')`, слушатель
снимается в cleanup перед `app.destroy()`.

**Вид фона — по теме** (`backdropLook` в `mapRenderer.ts`, 07.10.2026; ближний
слой и вуаль кладбища — 08.10.2026):

| Тема | Ближний слой | Вуаль `bgDim` | Масштаб картинки |
|---|---|---|---|
| `graveyard` | непрозрачен (до 08.10.2026 — 0.55) | `0x18161e` на 0.42 (до 08.10.2026 — 0.22) | высота 1800 px МИРА (× `WORLD_SCALE` на экране) |
| `throne_room`, `flooded_crypt` | непрозрачен | `0x0e0c13` на 0.42 | по высоте экрана |

У кладбища цвет вуали и масштаб взяты из одобренного предпросмотра карт A и F: слой
платформ подбирался именно под такое кадрирование. Картинка фона привязана к
миру, а не к экрану, поэтому на телефоне в начале карты кадрирование совпадает с
предпросмотром; дальше слои расходятся с ним параллаксом — так и задумано.
⚠️ Высота 1800 — НИЖНЯЯ граница: на экране выше такой картинки (планшет,
десктоп) фон дотягивается до высоты экрана, иначе плитка `TilingSprite`
повторилась бы по вертикали.

⚠️ **Ближний слой кладбища — НЕПРОЗРАЧНЫЙ (решение дизайнера 08.10.2026), и
этим фон игры намеренно отличается от предпросмотра.** В предпросмотре слой
лежит с 0.55; так он и был перенесён 07.10, и в игре это выглядело
полупрозрачным и блёклым. Замер 08.10.2026: рецепт был перенесён точно (в точке
без параллакса фон игры отличался от одобренной картинки на 2.8 из 255 в
среднем) — «призрак» давал сам рецепт: собственная альфа слоя 0.87 × 0.55 —
плотность в среднем 0.48 и нигде не выше 0.55. Теперь слой кладётся как есть:
прозрачные участки самой картинки (49% её площади) остаются прозрачными, и
дальний слой виден сквозь них, а не сквозь камень.
⚠️ **Вуаль кладбища — 0.42 (решение дизайнера 08.10.2026), в предпросмотре
0.22 — второе намеренное расхождение.** На плотном ближнем слое с 0.22 платформы
сливались с фоном: ближняя архитектура — тот же камень с тем же мхом, и её
карнизы читались как полки. Замер по четырём кадрам (A и F, начало и середина
карты, 390×844):

| | Фон к яркости платформ | Доля фона не темнее типичной платформы |
|---|---|---|
| вуаль 0.22 | 0.86 | 36% |
| вуаль 0.42 (в игре) | 0.70 | 12% |
| прежняя плиточная A | 0.65 | 17% |
| карта B | 0.63 | 19% |

Цвет вуали прежний, `0x18161e`, — меняется только плотность (`dimAlpha`).
⚠️ `tools/build_map_art.mjs` по-прежнему кладёт ближний слой с 0.55 и вуаль с
0.22 — и так должно быть: это фон ЗАМОРОЖЕННЫХ снимков, по нему скрипт
воспроизводит сборки байт в байт и сверяет слой платформ. К виду игры он
отношения не имеет.

⚠️ **Фон кладбища мыльный — исходник мал, и крупнее его НЕТ (замер
08.10.2026).** Одобренные слои — это сами оригиналы генерации: дальний
1405×1119, ближний 1402×1122 (sha256 совпадает с файлами в папке Codex
`generated_images`; в архиве арта, в `art-src/`, в загрузках и на рабочем столе
версий крупнее нет). Картинка кладётся высотой 990 CSS px, поэтому на экране она
растянута:

| Экран | Фон | Платформы |
|---|---|---|
| ПК, плотность 1.25 | ×1.10 | ×0.69 |
| телефон, плотность 2 | ×1.77 | ×1.10 |
| телефон, плотность 3 | ×2.65 | ×1.65 |

При плотности 3 игра рисует кадр с плотностью 2 (`resolution = min(dpr, 2)`), а
браузер дотягивает его ещё в 1.5 раза. Фон в 1.6 раза мягче платформ при ЛЮБОЙ
плотности — это заложено в одобренном кадрировании (1119 px картинки на 1800 px
мира); к тому же сам исходник мягче: мелкой детали в нём 9.4 против 14.0 у слоя
платформ. Пока ближний слой лежал с 0.55, это было менее заметно.
Решение дизайнера 08.10.2026: **оставить как есть, фон увеличить отдельной
задачей у Codex; растягивать имеющийся — нельзя** (растяжка деталей не добавит).
Что нужно от новой картинки: высота от 1800 px, чтобы сравняться с платформами,
и 1980 px (около 2486×1980), чтобы на плотности 2 лечь пиксель в пиксель.
Игре для замены правка кода НЕ нужна — масштаб считается от высоты текстуры, —
но потолок размера файла фона в `build_map_art.mjs` (`BACKDROP_MAX`, 600 КБ)
под картинку втрое больше придётся поднять.

### Грабли текстур карты (выстраданы, не наступать)
- **`texSrc()`: атлас 8 КОЛОНОК × 4 СТРОКИ, не 8×8.** Брали остаток от 8
  и по Y тоже — для `y % 8 >= 4` координата уходила НИЖЕ нижний край
  картинки, и `drawImage` молча рисовал пустоту БЕЗ единой ошибки в
  консоли. На карте A все три этажа (y=6,13,20 — остатки 6,5,4) попали
  в этот диапазон, поэтому кладки не было нигде.
- **Светлая «истёршая» кромка есть только в ВЕРХНЕЙ строке атласа**
  (у `masonry_graveyard` нижние строки ровные — замерено по яркости).
  Поэтому файлы-поверхности всегда берут строку 0, а файлы под землёй —
  строки 1..3. Разнообразие даёт горизонталь (8 колонок). Иначе полы
  разных этажей выглядят по-разному.
- **Не файлить одну и ту же ячейку и на поверхности, и под землю** —
  светлая кромка повторяется на каждом ряду и читается как «лестница».
- **Старый атлас имел тёмные полосы ~5-6px между ячейками**, они
  «протекали» в игру как трещины между камнями — лечилось обрезкой
  `INSET`. В НОВЫХ атласах полос нет (проверено замером яркости на
  границах), `INSET` снижен до 2px.
- **`Assets.load()` реджектит промис при 404**, в отличие от
  `loadSprites()` в `mapRenderer.ts` (та всегда резолвится). Поэтому один
  недостающий PNG параллакс-фона обрывал ВСЮ инициализацию: пропадали и
  твердь, и геймплей — игрок получал каменный экран ошибки из-за картинки,
  которая ни на физику, ни на бой не влияет.
  ✅ **ЗАКРЫТО 04.10.2026:** оба слоя грузятся через `loadBackdropLayer`
  (`Explore.tsx`) — свой try/catch на КАЖДЫЙ слой (дальний и ближний
  независимы, промах одного не забирает второй), промах даёт `console.warn` и
  `null`, и забег идёт без этого слоя: спрайт не создаётся, `tileScale` и
  `tilePosition` не трогаются (в тикере и в обработчике resize стоят проверки
  на `null`). Затемнение добавляется ВСЕГДА — это плашка настроения, а не часть
  фона, и от неё зависит читаемость карты поверх.
  ⚠️ Это НЕ общее правило «глушить ошибки загрузки». У сетки, слот-файлов и
  листов спрайтов всё наоборот: без них забега нет, и их промах обязан быть
  виден (экран ошибки, предохранитель `LOAD_WATCHDOG_MS`). Фон — единственный
  слой, отсутствие которого игра переживает.
- **Полноаливое проглатывание ошибки загрузки** (`img.onerror` без лога)
  стоило нескольких итераций вслепую — в `loadSprites()` теперь
  `console.error` с путём.

### Расстановка декора по картам (`place_decor.py`)

⚠️ **`place_decor.py` — ВНЕШНИЙ инструмент, вне репозитория, лежит у Андрея
на машине.** Искать его в `tools/` бесполезно, там его нет и не будет.
Правила ниже — то, что скрипт реализует; они нужны, чтобы проверить
результат его работы и повторить раскладку, если скрипт понадобится заново.

Декор в `map_X_slots.json` лежит массивом `decor: [{x, y, type}]`. Раскладка
делается офлайн-скриптом, НЕ вручную и НЕ рандомом в рантайме — иначе объекты
висят в воздухе и врастают в потолок.

Правила (согласованы с Андреем, менялись по ходу — здесь итоговые):
- **Опора обязательна**: напольный декор ставится в клетку, под которой `#`
  или `=`. Подвесной (`crypt_hanging_chains`) — только под клеткой `#`,
  НЕ под `=`: цепь с тонкой однoклеточной платформы читается как ошибка,
  не за что цепляться. Под цепью ≥3 клетки воздуха, разнос между цепями
  ≥5 тайлов.
- **Высота проверяется**: `headroom` считает воздух над клеткой, объект выше
  запаса не ставится (густое дерево 4 тайла не влезет под низкий потолок).
- **На платформах `=` — только мелочь** (≤1.6 тайла: кости, груда золота,
  раскопанная могила). Крупное — только на сплошной `#`.
- **Зона чистоты ТОЛЬКО вокруг гейм-точек** (1 тайл). Изначально закладывал
  чистоту вокруг всего геймплея — Андрей отверг: декор не имеет коллизии и
  служит восприятию карты, вылизанные пустоты вокруг каждого объекта делают
  карту беднее. К врагам/наградам декор подходит вплотную, поверх их клетки
  не встают. Вокруг НПС/босса/старта — 1-2 тайла (окно диалога, обзор).
- **Отступ от краёв карты** (x=0 и x=W-1 пропускаются) — иначе объект
  срезается краем экрана.
- **Группами по 1-3** с интервалом ~4 сверху / ~2 внизу: ниже по карте
  гуще (нижние этажи обжитее). Тип выбирается ВЗВЕШЕННО, не жёстким
  отбором: крупное тяготеет к стенам, мелкое к открытым местам, повтор
  подряд глушится ×0.25. Жёсткий топ-3 по размеру пробовал — половина
  набора (фонари, статуи) не выпадала вообще.

Плотность на выходе: карта A — 48 объектов, карта B — 34 (на B меньше:
верхнее плато почти целиком занято врагами/наградами/шипами).

Валидатор проверяет: опору, высоту, потолок для цепей, дубли, попадание на
геймплейную клетку, край карты. Обе карты — 0 ошибок.

**Превью до применения:** офлайн-рендер на Python (PIL) повторяет логику
`mapRenderer.ts` (тот же атлас 8×4, тот же выбор строки, тот же 0.42 dim) и
даёт PNG всей карты + кроп в масштабе 1:1. Смотреть надо кроп: общий план
3072px мельчит и ничего не видно, а игрок видит ~1100px участок.

## Как делается карта — процесс

Геометрия и инструменты — в скилле `right-place-maps`; здесь ПОРЯДОК
работы. Роли: чат — дизайн и генерация, Claude Code — внесение файлов,
Андрей — финальный визуальный судья.

### Золотой цикл

1. **Концепт одной фразой** («спуск к боссу», «две башни и мост») —
   согласовать ДО сетки.
2. **Каркас**: этажи и подъёмы только проверенными функциями
   `tools/map_tools.py` (`stairs`, лестничная башня). Руками — ничего.
3. **Проверка**: обе волны + `lint` + `debug()`. Чинить по ASCII-отладчику.
4. **События**: слоты `hazard`/`reward`/`enemy` по правилам скилла (комбо в
   узких местах, 1 тайл чистоты). ⚠️ **Снова обе волны — шипы меняют
   проходимость.**
5. **Рендер**: полная карта + зумы подъёмов, отдать Андрею.
6. **Визуальный тест**: вопрос «как отсюда выбраться?» не должен возникать.
   Замечание → чинится ТОЛЬКО указанное место → снова п.3.
7. **Приёмка**: файл сетки в репозиторий + строка в пул + слоты в конфиг.

### Definition of Done карты

Файл сетки + строка в пуле + слоты, обе волны 100%, линтер чист, зумы
подъёмов показаны, визуальное «ок» Андрея получено, изменение
закоммичено. Только после этого — следующая карта.

### Жёсткие уроки (нарушение = переделка)

- **Числа не отменяют глаз.** Трижды граф говорил «ок», а глаз ловил
  нечитаемость. Проверки — необходимое условие, приёмка только визуальная.
- **Off-by-one в лестницах**: игрок стоит на ряд ВЫШЕ верха столба. При
  любой странности стыковки — сначала печать зоны отладчиком, потом
  гипотезы.
- **Две неудачные итерации подряд — элемент отлаживается на пустом поле
  отдельно.** Не спамить неудачными попытками, показывать рабочий результат.
- **Одна правка за шаг.** Вернуть «как было» — это тоже правка.

### Якоря рендера (`render_lib.py`)

⚠️ **`render_lib.py` — ВНЕШНИЙ инструмент, вне репозитория, лежит у Андрея
на машине.** Ниже — что он делает и какие числа задаёт; открыть его из
репозитория нельзя, искать не надо.

Порядок слоёв: фон 2 слоя (небо ×0.1, арки ×0.3, анкер к земле) → силуэты

фасадах, цепи с потолков → игрок.
Опора объекта: **верх платформы = `y*T + 38`, верх тайла = `y*T`**
