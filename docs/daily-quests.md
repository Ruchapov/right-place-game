# Ежедневные задания (сервер, 26.10.2026)

С 5 уровня у героя есть набор из 3 заданий. Он делает их по одному, за каждое
выполненное получает золото, значки охотника (новая валюта) и 1 RP.

Сделана ТОЛЬКО серверная часть. Клиента (доска заданий) нет — отдельная задача;
её арт уже лежит в `public/assets/quests/` и `docs/quest-board-*` (не в git).

| Что | Где |
|---|---|
| Каталог (общий, байт в байт) | `src/quests.ts` ↔ `server/src/quests.ts`, сверка — `tools/check_potion_sync.py` |
| Правила, форма состояния, подсчёт прогресса (чистые функции) | `server/src/questState.ts` |
| Ручки заданий | `server/src/routes/quests.ts` |
| Прогресс и награда на финише | `POST /run/finish-explore`, `server/src/routes/run.ts` |
| Колонки | `Character.hunterBadges`, `Character.rp`, `Character.questState`; миграция `20261026120000_daily_quests_add` |

Требования (`QuestRequirement`):
- `attackSkill` — надет хотя бы один навык, кроме `QUEST_NON_ATTACK_SKILLS`
  (сейчас `['heal']`: исцеление врагов не поражает);
- `anySkill` — надет хотя бы один навык.

Проверяются **в момент броска** (новый набор, замена). Снять навык после того,
как задание выпало, его не убирает. «Только сталь» после выпадения можно
облегчить, забыв навык, — но «Забыть» стоит книги (она не возвращается).

### Награда

```
награда = ceil(2 × уровень × процент / 100)   // золота и значков охотника поровну
        + 1 RP
```

`questReward` в общем каталоге: одна формула на доску и на финиш. Уровень —
серверный, `calculateLevel`. На финише — **уровень ДО этого забега**
(`characterLevel` обработчика): ровно та награда, что доска показывала на
задании, а не больше из-за уровня, набранного этой же вылазкой (решение
сессии). Вид заданий в ответе финиша — уже по уровню после забега.

Примеры: 5 ур., «Вылазка» (140%) — 14; 7 ур. — 20; 7 ур., «Зверобой» (80%) —
ceil(11.2) = 12.

## Правила набора

| Правило | Как сделано |
|---|---|
| До 5 уровня набора нет | `QUEST_UNLOCK_LEVEL = 5`; `questState` остаётся NULL, ручка отдаёт `unlocked: false` |
| Набор — 3 разных задания, случайно из доступных | `settleQuestState` → `rollQuestSet`; требования — по надетым навыкам на момент броска |
| Активно одно задание | `active` в состоянии; место в наборе — `active` |
| Взять можно любое невзятое из набора | статус места `open`; иначе 400 |
| Взял другое при активном — активное пропадает с прогрессом | место прежнего — `lost`; переходящее просто пропадает |
| Шаг = выполненные + пропавшие задания набора (0, 1, 2) | `questStep` |
| На каждом шаге одна замена невзятого задания | `replacedAtStep` — шаг, на котором замена потрачена; есть, пока он не равен текущему шагу. Не использовал — на следующем шаге всё равно одна |
| Замена — не из тех, что в наборе, и не активное | исключаются все три задания набора (и заменяемое тоже) и активное (в т.ч. переходящее) |
| Таймер 8 ч — с первого взятого задания набора | `setStartedAt`; замена таймер не запускает |
| Истёк — новый набор из 3, лениво, без крона | при любом обращении: GET, take, replace, финиш |
| Невзятые старого набора пропадают; недоделанное активное остаётся | активное становится переходящим (`carried: true`) со своим прогрессом |
| Взял задание нового набора — переходящее пропадает | как обычная потеря активного |
| Пока идёт вылазка — брать и менять нельзя | 400 `Run in progress`; смотреть (GET) можно |

Решено сессией (в задаче не было, — сказать, если не так):
- **Переходящее не попадает в новый набор** — иначе взять его же из нового
  набора значило бы потерять прогресс.
- **Набор не обновляется, пока ни одно задание не взято**: таймер не запущен,
  набор лежит сколько угодно.
- **Все три выполнены раньше 8 ч** — новый набор только по таймеру.
- **Финиш тоже приводит набор к «сейчас»**: герой, дошедший до 5 уровня, или
  истёкший таймер получат набор в ответе финиша.

## Прогресс

Засчитывается **только вылазка, закрытая финишем с `died: false`**. Смерть, выход
шестерёнкой (клиент шлёт его смертью, `sendFinishExplore(true)`), штрафной путь
неподтверждённого забега и вылазка, закрытая входом, не дают ничего. Растёт
только активное задание (в т.ч. переходящее), прогресс копится между вылазками
и не превышает цели. Дошло до цели — выполнено: награда в той же условной записи
финиша (`gold`, `hunterBadges`, `rp` — `increment`), место — `done`.

| metric | Источник | Сверх этого |
|---|---|---|
| `runs` | +1 за вылазку | |
| `runNoPotion` | +1, если `currentRun.potionsDrunk` пуст (запись `/run/sip`) | не со слов клиента; испорчено — не засчитано |
| `beastGroups` / `zvonarGroups` / `gatekeeperGroups` | закрытые `enemy`-события по `enemyKind` своего `currentRun` | нет поля (забег старого сервера) — звери |
| `chests` | закрытые `chest`-события | мимик тоже |
| `mimics` | закрытые `chest` с `isMimic: true` | |
| `obelisks` | закрытые `obelisk`-события | |
| `skillHits` | `skillUses` финиша после потолков (тот же, что растит уровни навыков), без `QUEST_NON_ATTACK_SKILLS` | |
| `parries` | тело: `parries` | |
| `manaCollected` | тело: `manaCollected` | срезается до `2 × убитых` (`RUN_MANA_DROP_MAX`); убитые — все враги и боссы забега |
| `manaSpent` | тело: `manaSpent` | срезается до `10 + 2 × убитых` (`RUN_MANA_MAX` + собранное) |
| `runNoSkills` | +1, если тело `skillCasts === 0` | |
| `runNoSpikes` | +1, если тело `spikeHits === 0` | |
| `fastRun` | +1, если от `confirmedAt` (иначе `startedAt`) до финиша меньше 3 мин, часы сервера | нет ни того, ни другого — не засчитано |

Закрытые события — те же провалидированные `closedEvents`, по которым
начисляются трофеи. Срез маны пишет `warn`
`finish-explore: quest mana counters exceeded what the run could give, clamped`.

### Пять новых счётчиков тела финиша — договор для клиента

⚠️ **Поля нет (старый клиент) — «неизвестно», а не ноль**: задание на этом
счётчике не продвигается. Иначе «Тихий шаг» и «Только сталь» у старого клиента
выполнялись бы сами. Поле есть, но не целое неотрицательное — тоже
«неизвестно», финиш не падает, `warn`
`finish-explore: quest counters malformed, treated as unknown`.

| Поле | Что считать клиенту |
|---|---|
| `parries` | успешные парирования за вылазку — удар не прошёл благодаря 🔄 (`takeDamage`/`takeRamDamage` вернули «отбил»; отбитый шип босса и волна Звонаря тоже) |
| `manaCollected` | единицы маны, долетевшие до героя, **даже при полном запасе** (шар долетел — +1, сгорела ли мана, не важно) |
| `manaSpent` | единицы маны, **снятые с запаса** навыками. Бесплатное применение Повелителя — 0; недостача, оплаченная кровью Владыки, — не мана. Иначе сервер срежет до потолка |
| `spikeHits` | попадания на шипы КАРТЫ (урон от шипа карты) |
| `skillCasts` | ВСЕ применения навыков: и промахи, и исцеление, и бесплатные у Повелителя. По мане считать нельзя (бесплатные её не тратят) |

### «Быстрые ноги»

`POST /run/ready` с 26.10.2026 пишет в `currentRun.confirmedAt` момент
подтверждения (часы сервера). Финиш меряет от него; если его нет (забег
подтвердили глотком или срезом, или он начат до правки) — от `startedAt`: это
всегда дольше, то есть против игрока. Повтор финиша после 409 меряется заново,
тоже против игрока.

## Хранение

Колонки `Character`: `hunterBadges Int @default(0)`, `rp Int @default(0)`
(поля под RP раньше не было), `questState Json?`. Миграция
`20261026120000_daily_quests_add` — только `ADD COLUMN`; **создана, НЕ применена**
(применяет Андрей).

`questState`:

```
{
  set: [{ id, status: 'open' | 'active' | 'done' | 'lost' }, …3],
  setStartedAt: number | null,     // мс, часы сервера; null — таймер не запущен
  replacedAtStep: number | null,   // шаг, на котором потрачена замена
  active: { id, progress, carried } | null
}
```

Читать **только через `readQuestState`** — три состояния, как у
`readSmugglerDeal`: `none` (NULL), `state`, `malformed`. Строгий разбор проверяет
и согласованность: ровно одно место `active` у активного задания из набора, ни
одного — у переходящего или без активного; переходящего нет в наборе; прогресс
меньше цели; без повторов; `replacedAtStep` 0..2.

| Где испорчено | Что будет |
|---|---|
| вход | 200, `log.error` `login: corrupt questState` |
| финиш | 200, задания не трогаются, `quests: null`, `log.error` `finish-explore: corrupt questState — quests skipped` |
| ручки заданий | 500 `Corrupt quest state`, `log.error` |

Все записи состояния **условные**: фильтр по прежнему `questState`
(`questStateFilter`, `routes/run.ts`), 0 строк — 409 `State changed, retry`, не
записано ничего. Финиш считает задания от `questState`, перечитанного **под
блокировкой строки** (`lockCharacterRow`) внутри своей транзакции, и пишет его
той же записью, что закрывает забег, — повтор финиша награду второй раз не
начислит.

## Эндпоинты

| Ручка | Тело | Что делает |
|---|---|---|
| `GET /character/quests` | — | Состояние заданий. Приводит его к «сейчас» (первый набор с 5 ур., новый набор по истёкшему таймеру) и, если набор выпал, **пишет** — иначе следующий запрос бросил бы набор заново. Посреди вылазки работает |
| `POST /character/quests/take` | `{questId}` | Взять задание набора |
| `POST /character/quests/replace` | `{questId}` | Заменить невзятое задание набора |

Ответ всех трёх: `{ quests: QuestView, hunterBadges, rp }`.

```
QuestView = {
  unlocked: boolean,          // уровень ≥ unlockLevel
  unlockLevel: 5,
  set: [{ id, status, goal, progress /* только у активного, иначе null */, reward: {gold, hunterBadges, rp} }],
  replaceAvailable: boolean,  // есть ли замена на этом шаге
  nextSetInMs: number | null, // через сколько мс от ответа придёт новый набор; null — таймер не запущен
  carried: { id, goal, progress, reward } | null   // переходящее
}
```

Награда в виде — на текущем уровне героя. Названия и описания клиент берёт из
своего каталога по id. `nextSetInMs` — относительным числом, а не моментом
(часы телефона с сервером не сверены).

Отказы take / replace: 401; 404 `Character not found`; 400 `Unknown quest`,
`Run in progress`, `Quests locked` (с `unlockLevel`), `Quest not in set`,
`Quest already taken`, `No replacement on this step` (только replace),
`No quest to replace with` (недостижимо при нынешнем каталоге); 500
`Corrupt quest state`; 409 `State changed, retry`. **На отказе не пишется
ничего** — даже набор, выпавший при приведении к «сейчас»: его запишет следующий
GET, а вид, которого нет в базе, клиенту не отдаётся.

Изменения в старых ручках:
- `POST /run/finish-explore` — в теле пять счётчиков выше; в ответе
  (`RunResultSummary`) `gold`, `hunterBadges`, `rp` (абсолютные, перечитанные),
  `questCompleted` (`{questId, gold, hunterBadges, rp}` или `null`) и `quests`
  (`QuestView` после забега или `null`). Повтор финиша отдаёт сохранённый ответ —
  с видом заданий на момент первого финиша.
- `POST /run/ready` — пишет `currentRun.confirmedAt`.
- `POST /auth/login` — `character.hunterBadges`, `character.rp`; сырой
  `questState` из ответа вырезан (состояние заданий — только своей ручкой).
  `interruptedRun` дополнен теми же полями, что финиш: `questCompleted: null`,
  `quests: null` (вход задания не трогает и не отдаёт).
- `GET /character/profile` — `hunterBadges`, `rp`.

## Выкладка

Порядок: **миграция → сервер**. Сервер без миграции уронит вход (Prisma читает
новые колонки в каждом чтении персонажа). Старый клиент с новым сервером
безопасен: лишние поля ответов он не читает, счётчиков не шлёт — задания на
счётчиках у него не продвигаются, остальные растут по финишу. Задания, правда,
у старого клиента не видны и не берутся вовсе — пока нет доски, активного
задания ни у кого нет, и финиш только бросает набор (с 5 ур.).

⚠️ Копия `RunResultSummary` в `src/api.ts` новыми полями **не** дополнена (по
задаче клиент не трогали) — сделать в задаче клиента вместе с типами
`QuestView` и ответов трёх ручек.
