# Right Place — карты: геометрия и проходимость

Единственный источник правды для реализации этой модели —
`tools/map_tools.py` (физически может лежать вне репозитория, например
`Desktop\assets\map_tools.py` — уточняй актуальный путь у Андрея). Этот
файл описывает ПРАВИЛА, `map_tools.py` — их РЕАЛИЗАЦИЮ. Если они разошлись,
`map_tools.py` не автоматически прав — сверяйтесь и правьте то, что устарело.

⚠️ **Этот документ создан заново в текущей сессии** — до этого в проекте не
было отдельного SKILL-файла про карты, хотя `map_tools.py` и `render_lib.py`
уже на него ссылались в докстрингах. Правила ниже собраны из фактического
кода (`build()` в `map_tools.py`, комментарии `stairs()`/`plat()`,
`PLAYER_HEIGHT` в `Explore.tsx`) — не выдуманы, но раньше нигде не были
записаны одним текстом. Если где-то найдётся более старая/другая версия
этого документа — приоритет у неё, обнови этот файл под неё.

## Сетка

Карта — прямоугольная сетка символов, `.txt`, ряды разделены `\n`. Один
символ = один тайл (в рендере `TILE_SIZE = 64px`, см. `mapRenderer.ts`).

| Символ | Смысл |
|---|---|
| `.` | Воздух |
| `#` | Твердь (сплошная кладка) |
| `=` | Тонкая платформа — см. правила ниже |
| `^` | Шипы (визуально/геймплейно опасны, для геометрии проходимости — как воздух: `free()` их НЕ считает твердью, `is_solid`-подобные проверки их не пускают в `S`, но и не блокируют движение сквозь них как стена) |

Игровые события (враг/сундук/ловушка/NPC/босс/обелиск) и декор — это
**отдельные JSON-слот-файлы** (`map_X_slots.json`, координаты `[x,y]`), НЕ
символы в `.txt`-сетке. В сетке кодируется только геометрия проходимости.

## Игрок и модель прыжка

- Игрок занимает **2 тайла в высоту**, стоит "ногами" на верхней кромке
  тайла-опоры (`surface_y = y*TS`).
- Клетка стояния `S` — клетка `(x,y)`, где `(x,y)` и `(x,y-1)` воздух
  (голова помещается), и `(x,y+1)` — твердь (`'#'` или `'='`).
- Прыжок между двумя клетками стояния `a → b` разрешён (`can(a,b)`,
  `dy = ay-by`, `dx = |ax-bx|`) если:
  - падение (`dy<0`): `dx ≤ 5`
  - по прямой (`dy==0`): `dx ≤ 4`
  - вверх на 1 (`dy==1`): `dx ≤ 3`
  - вверх на 2 (`dy==2`): `dx ≤ 2`
  - вверх на 3 и больше: **запрещено всегда**
- Вверх (`dy>0`) дополнительно проверяется коридор — на пути от `(ax,ay)`
  до `(bx,by)` не должно быть занятых тайлов (см. правило про `'='` ниже).
  Не путать с рендер-коллизией (Explore.tsx) — там та же модель, но с
  пиксельной точностью и с `PLATFORM_H_RATIO` для полосы `'='`.

## `'='` — тонкая платформа (правило изменено в этой сессии)

**Было:** one-way платформа — проходима снизу вверх свободно, останавливает
только сверху.

**Стало (соулс-лайк, решение Андрея):**
- **Блокирует движение снизу вверх** — как удар головой о твердь. Блокирует
  только САМА ПОЛОСА (верхние `PLATFORM_H_RATIO ≈ 44%` клетки, прижата к
  верху клетки), нижние ~56% клетки над `'='` — свободный воздух.
- Сверху — твердь, встать можно (как и было).
- Сбоку — по-прежнему свободно проходима.
- Это осознанно расходится с интуицией "one-way platform" из других игр.
  Рендер (`mapRenderer.ts` → `drawPlatform`, `PLATFORM_H_RATIO`) и коллизия
  игрока (`Explore.tsx`) синхронизированы на эту модель.

## Правило 1 — обязательный подъём только кладкой `'#'` (ЖЁСТКОЕ требование)

> `'='` — ТОЛЬКО необязательные мосты/срезки. Если это ЕДИНСТВЕННЫЙ путь
> наверх (или назад) между двумя точками карты — это ошибка карты, а не
> валидный дизайн.

Причина: `'='` теперь блокирует подъём снизу (см. выше) — если убрать её
физически с карты или изменить модель ещё раз, всё, что держалось только на
`'='`, немедленно перестаёт быть проходимым без предупреждения. Обязательные
подъёмы должны стоять на сплошной кладке `'#'` (лестница — см. `stairs()` в
`map_tools.py`), чтобы проходимость не зависела от трактовки `'='`.

Это правило **не рекомендация, а жёсткое требование** — карта не считается
готовой, если она его нарушает, независимо от того, что `report()` показывает
"туда/обратно 100%".

**Проверяется автоматически: `lint_ascent(f, start)`** в `map_tools.py`.
Сравнивает модель "только стены" (`build_walls`) с штатной моделью
(`build`, где `'='` тоже блокирует подъём) — разница = список координат,
где обязательный путь держится на `'='`. Пустой список = правило соблюдено.

⚠️ **Все 6 карт пула (A–F, включая оба состояния D — OPEN/SEALED) сейчас
нарушают это правило** — они спроектированы под старую one-way-модель `'='`
и ждут точечной правки под новое правило. Не считать их эталоном при
проектировании новых карт; `lint_ascent()` перед сдачей — обязателен.

## Инструментарий (`map_tools.py`)

| Функция | Назначение |
|---|---|
| `build(g)` | **Штатная** модель прыжка (см. выше, `'='` блокирует подъём) |
| `build_legacy(g)` | Старая модель без проверки коридора (для сравнения/истории) |
| `build_walls(g)` | Промежуточная: коридор проверяется, но только `'#'` (без нового правила `'='`) — нужна для `lint_ascent` |
| `wave(S, can, start, reverse=False)` | BFS/DFS-волна достижимости от `start` (или до `start`, если `reverse=True`) |
| `report(f, start)` | Итог по карте: % достижимости туда/обратно (использует штатную `build`) |
| `lint(f)` | Линт: платформы `'='` короче 2 тайлов (слишком узкие) |
| `lint_ascent(f, start)` | **Главный инструмент для правки под новое правило** — см. выше |
| `debug(g, start)` | ASCII-визуализация достижимости (`·` полностью ок, `▲` только туда, `×` не дойти) |
| `stairs(g, ...)` | Генератор зиккурат-лестницы из кладки `'#'` — правильный способ строить обязательный подъём |
| `plat(g, x, y, w)` | Генератор полосы `'='` — только для необязательных мостов/срезок (см. правило 1) |

Типовой цикл правки карты: `lint_ascent(f, start)` → для каждой найденной
точки решить, конвертировать ли ведущий туда `'='` в кладку `'#'`/`stairs()`
— → `report(f, start)` и `lint(f)` на чистоту → `debug(g, start)` глазами
перед сдачей.

## Когда НЕ использовать этот skill

- Рендер тайлов/декора (текстуры, обводка, `PLATFORM_H_RATIO` как визуальный
  параметр) → `mapRenderer.ts` / `render_lib.py`, не сюда.
- Физика/коллизия игрока в реальном времени (гравитация, прыжок, тач-кнопки)
  → `pixijs-conventions`.
- Слоты событий (враг/сундук/NPC/босс) — своя JSON-схема, вне геометрии.
